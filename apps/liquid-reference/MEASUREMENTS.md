## Motion model

The continuous route holds Account for 0.8 s, slides left → right → left at 1,000 / 250 / 1,000 pt/s, holds for 1.2 s, then releases and records two seconds of settling. For a spring, `x″ + 2ζ√k x′ + kx = k target`. Cranpose follows the pointer with ζ = 0.85 and k = 650. Contact growth uses ζ = 1, k = 600; release uses ζ = 1, k = 650 and an 8 ms delay. The enclosing surface uses ζ = 0.65, k = 500 and a 16 ms delay. Geometry scales use measured point inflation rather than a ratio tied to the simulator width.

The shape response uses a relaxing speed state `r′ = λ(|v| − r)` and independent damped width/height modes with forcing `a r + b r′`. This keeps inertial strain when a drag stops and produces the same stretch for either travel direction. Width parameters `(ζ, k, λ, a, b)` are `(0.430087, 164.807, 6.059487, 0.00001663016, 0.00004602218)`; height uses `(0.38644, 198.37253, 3.179867, −0.00008953011, −0.00008536202)`. These identify an approximate response, not Apple's internal solver. Position is measured relative to the enclosing surface so a common translation cannot become a strain impulse. Elastic deformation remains independent of touch activity: releasing the finger changes the base size and material, but must not multiply away the spring tail. The release regression fails when that activity multiplier is restored. The resting hierarchy and active UIKit wrapper require different layer identities; both are followed through every frame.

The 25% reversal is the calibration route. The remaining tint levels and independent directional routes are validation data. The response regression requires per-axis strain RMS below 0.025 and verifies both stretch and compression. Removing the inertial term fails it; reversing the trajectory preserves the shape. This is not a pixel-perfect tolerance.

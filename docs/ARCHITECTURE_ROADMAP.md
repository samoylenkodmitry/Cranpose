# Cranpose Architecture Roadmap

This roadmap tracks the internal ownership rewrite needed to make Cranpose viable for large apps across desktop, web, Android, and future iOS support. Public composable APIs, `Modifier`, text, layout, `MeasurePolicy`, `AppLauncher`, and renderer entry points should remain source-compatible while runtime ownership and frame execution change underneath.

## Target Shape

```text
PlatformDriver
  AppShell<R>
    AppContext
      UiInvalidationState
      Density, viewport, input scale
      TextService
      LayoutStore and FrameLayoutArena
      NodeRegistry and dispatch state
      FrameScheduler
    Composition and MemoryApplier
    Scene builder and RenderGraph
    RendererContext
      WgpuFrameGraphExecutor
        UploadAllocator
        TransientTexturePool
        Pass DAG
        frame submit boundary
```

The rule is strict: `AppShell` owns mutable app/runtime state, and the WGPU frame graph executor owns GPU submission. Other systems record intent.

## Completion Gates

- Desktop demo performance must sustain more than 120 FPS on the reference Linux/X11 development machine for idle and common interactive paths after the frame-graph/layout ownership work lands. Regressions below that budget are framework blockers, not demo quirks.
- Desktop demo performance gates must fail on frame pacing, not only average FPS. A path can report `>120 FPS` while p95 frame intervals exceed 35 ms; Markdown scrolling is the current proving case and must stay covered by the visible-X11 perf robot.
- Renderer validation must include external X11 presented-window screenshots, not only renderer readback. The Text tab struck-through and underlined text artifacts are guarded by captured X11 crops plus focused continuity contracts so dashed, gapped, or scroll-unstable decoration lines fail visibly and automatically.
- Native Winamp peer windows must remain movable through the visible desktop path. Robot tests that claim to move those windows must assert external X11 window geometry changes, otherwise the test is not proving the user-visible behavior.
- Visual comparison gates must keep before/after origin-main captures for desktop-demo and downstream apps when renderer architecture changes can affect scale, text decorations, shadows, effects, or window presentation.

## Progress

- AppContext exists and is owned by `AppShell`.
- Density, render invalidation, pointer invalidation, focus invalidation, layout repasses, draw repasses, and modifier-slice repasses route through the active `AppContext`.
- Production render-state access requires an active `AppContext`; test and `test-helpers` builds use an isolated per-thread `AppContext` harness. A static contract rejects hidden fallback runtime stores and `OnceLock<RenderState>`.
- Desktop declarative native-window requests are owned by the desktop `App` through `NativeWindowRegistry`; the thread-local only routes declarations during the active app update and stores no real request state.
- Desktop primary and native-window `AppShell` construction enters the app-owned `NativeWindowRegistry` before the initial stable render. Hidden-primary `run_windows` apps such as Cranamp declare their visible OS windows on frame zero instead of relying on a later recomposition to re-emit dropped declarations.
- Desktop Linux X11 native-window probing is owned by the desktop `App` through `NativeWindowPlatformProbe`; pointer and window-position queries no longer share a thread-local X11 client cache across app instances.
- Native-window dispatch state is stack-scoped: nested dispatch restores the outer drag handler, resize handler, and surface origin instead of clearing user-visible peer-window movement state.
- The visible Winamp native-window robot proves peer-window movement through external X11 geometry: group drags, one-pixel traces, fast drags, individual playlist/equalizer drags, and direct window-manager movement all change the real OS windows and preserve attachment invariants.
- Desktop performance has a visible-X11 FPS gate in `perf_robot_fps.sh`. The gate defaults to the production budget `>120 FPS`, runs the robot perf harness in immediate present mode, writes reports under the cache directory, and fails on any scenario below budget.
- The visible-X11 FPS gate now includes `markdown_scroll`, rolling p95/p99/max frame intervals, measured AppShell frame-work timing, 120 Hz / 60 Hz budget-miss counts, and 50 ms stall counts. The short Markdown probe reproduced the subjective jank report: average FPS can pass (`129.6 FPS`) while p95 fails (`38.12 ms > 8.33 ms`), with lazy reuse still healthy (`99.14%`) and WGPU submit count still one per sampled frame. That points the next fix at event/frame scheduling and frame-work attribution rather than item churn or local WGPU submit fragmentation.
- `robot_markdown_scroll_exact_external_contract` now also captures the real X11 window after the first pumped frame following each one-pixel scroll input. It fails if the presented crop still matches the old position better than the expected moved position, so Markdown jank regressions cannot hide behind a settled screenshot or an average FPS counter.
- Android host-window resize and overlay-position requests are owned by the Android runtime through `AndroidHostWindowRegistry`; the thread-local only routes declarations during the active Android shell update and stores no real request state.
- Android overlay JNI events are owned by the Android runtime through `AndroidOverlayEventQueue`; Java callbacks carry an explicit retained runtime queue handle, and Rust keeps no process-global overlay queue or helper-class cache.
- Desktop, web, and Android platform drivers update density through `AppShell::set_density()` instead of writing fallback UI state directly.
- Layout node registry state, virtual node ids, modifier-local parent lookup, scroll motion contexts, pointer repass queue, focus invalidation queue, focused text-field dispatch, cursor blink state, and draw snapshot observation are owned by `AppContext`.
- Scroll ids and scroll-motion invalidation callback ids are owned by their `ScrollState` / `ScrollMotionContext` instances instead of process-global counters.
- Layout cache epochs are owned by `AppContext`; one shell's remeasure no longer advances another shell's retained layout cache generation.
- Modifier-chain trace subscribers are owned by the active `AppContext`; debug tracing no longer uses a process-global callback slot.
- Fling velocity diagnostics are owned by `AppContext`; desktop robots query/reset them through the app-thread robot command channel instead of reading process-global UI test state from the driver thread.
- AppShell pointer, keyboard, clipboard, and IME entrypoints enter the owning `AppContext` before dispatching handlers, so event code observes the shell-local density, focus state, text services, and invalidation queues.
- Text-mutating clipboard and IME entry points run inside both the event-handler marker and an applied mutable snapshot. Paste, cut, IME preedit, and delete-surrounding handlers now see the same runtime scope guarantees as pointer and key input.
- Focused text-field dispatch validates the weak focus owner immediately before invoking the retained handler and clones the handler before callback entry, so stale destroyed fields cannot receive key, paste, copy, cut, delete-surrounding, or IME events.
- AppShell owns FPS/recomposition tracking. The process-global FPS publication API is gone; shell code reads `AppShell::fps_stats()`, and robot/perf diagnostics query the owning shell through the robot command channel.
- Web runtime frame wakeups are installed directly on the owning `AppShell`; wasm `set_frame_waker` is single-threaded and no longer needs a thread-local callback router.
- Suspending pointer-input coroutine wakeups route through the owning `AppContext` task registry and re-enter that context before polling resumed coroutine code.
- Pointer-input handler and task ids come from retained handler/task object identity instead of process-global atomics.
- Interaction-source ids use retained source identity and press ids are scoped to each `MutableInteractionSource`, not process-global counters.
- `ImageBitmap` and `SvgPainter` ids use retained pixel/painter identity instead of process-global image id counters.
- `ModifierLocalKey` identity is retained by the key token object instead of allocated from a process-global atomic counter.
- `FocusRequester` identity is retained by the requester token instead of allocated from a process-global atomic counter.
- `CompositionLocal` and `StaticCompositionLocal` identities are retained local-key objects instead of process-global numeric ids.
- Debug env flags for modifier metadata, core scope labels, and WGPU GPU stats are read at use sites instead of being latched in process-global `OnceLock` caches.
- Lazy graphics-layer observer scope ids are owned by each node observer instead of a process-global counter.
- Core state-chain assertion reads the current environment at the integrity-check boundary instead of latching `CRANPOSE_ASSERT_STATE_CHAIN` in a process-global cache.
- Core location-key and slot-validation diagnostics read their env flags at diagnostic boundaries instead of caching first access process-wide.
- Core location-key debug registry and collision diagnostics are thread-local debug state instead of process-global `OnceLock`/atomic state.
- Desktop-demo Winamp trace/debug env flags read the current environment at use sites instead of latching first access in `OnceLock<bool>`.
- LeetCodeDaily X11 robot capture id/window lookup state is owned by the runner thread instead of process-global statics.
- LeetCodeDaily robot image/decode/sharp-resize caches are owned by a runner-thread image cache instead of scattered process-global `OnceLock`s.
- Winamp native-window robot monitor geometry cache is owned by the runner thread instead of a process-global `OnceLock`.
- Snapshot v2 apply-observer handles retain their own observer identity instead of allocating ids from a process-global atomic counter.
- Live recompose-scope diagnostics are summed from registered runtime-owned counters instead of a process-global atomic.
- Recompose scope ids are derived from retained scope object identity instead of a process-global atomic counter.
- Runtime ids are allocated inside the runtime thread-local registry instead of a process-wide atomic counter.
- AppContext ids are allocated inside the AppContext thread-local routing registry instead of a process-wide atomic counter.
- Slot-table storage ids are derived from retained table-owned identity instead of a process-global atomic counter.
- Core runtime state allocation skips stale or occupied `StateArena` free-list entries and ignores stale lease registration, so allocator bookkeeping inconsistencies stay local instead of aborting remembered-state creation.
- Snapshot retained-record cleanup now uses explicit retained source records instead of optional-map unwrap postconditions, and fresh snapshot state construction sets its object id without asserting on a fresh `Arc` invariant.
- `SnapshotMutableState::promote_record()` reports a missing child record through its existing `Result` boundary, allowing snapshot apply to fail cleanly instead of aborting on a missing retained record.
- Snapshot mutable-state promotion and merged-record commit clone malformed record values through checked access, returning typed operation failure instead of panicking on record type drift.
- Snapshot mutable-state merge resolution treats malformed previous/current/applied record values as no merge, so snapshot apply can use its existing failure/conflict path instead of unwinding.
- Mutable snapshot apply uses the fallible `StateObject::try_readable_record` parent lookup. A missing parent-readable record now logs and returns `SnapshotApplyResult::Failure` instead of calling the strict `readable_record()` fallback.
- `MutableState` fallible APIs now return absence after the owning runtime is dropped, and `MutableState::set` skips released runtime state instead of aborting through a dropped-runtime lookup.
- Stale `State<T>` and `MutableState<T>` debug formatting uses fallible runtime access and reports unavailable handles instead of panicking during diagnostics after runtime teardown.
- Snapshot v2 runtime/global initialization returns concrete initialized handles directly; initialization no longer sets a thread-local `Option` and immediately asserts the value exists.
- Batched core command-stream application now reports malformed tag/payload state through `NodeError::MalformedCommandPayload`; missing payloads and invalid sync-child ranges are covered by focused tests instead of relying on command-application panics.
- Large mid-composition command flushes return the same command-stream `NodeError`; composer/recompose drop guards log errors they cannot propagate instead of panicking during cleanup.
- Root-render replay, invalid-scope replay, and `ComposeTestRule::pump_until_idle` loop exhaustion now return `NodeError::RecompositionLimitExceeded`; runaway test or stable-render compositions are reported through typed errors instead of panicking at the replay-limit guard.
- Composer creation no longer cross-binds an incompatible live `SlotsHost` or panics on it. If a slot host still belongs to another live runtime state, the new composer runtime receives a fresh slot host and the original host remains owned by its existing runtime state.
- Composer group-close cleanup logs detached-subtree handling failures and scope-stack underflow from guard paths that cannot return `Result`, avoiding panic-on-cleanup behavior.
- Slot-host pass cleanup now has a shared guard/finalization path. Strict callers still use `try_with_slot_host_pass`, while the convenience wrapper logs finalization failures after the body has run and returns the body result with a default outcome instead of panicking. Slot-host stack mismatches and subcompose-frame underflow are logged cleanup faults, not aborts.
- SlotsHost busy-state and finalization operations now use explicit error/log boundaries. `into_table()` reports live host references through `NodeError::SlotHostUnavailable`, `reset()` reports active passes through the same error type, duplicate `begin_pass()` calls are logged no-ops, and `finish_pass()` reports writer-invariant failures through `NodeError` instead of aborting on the debug validation path.
- Slot-writer empty-stack cleanup paths no longer abort. Finishing, skipping, or ending a group with no active writer group logs the malformed writer state and produces an empty result/no-op, while node recording without an active group reports an unretained insert instead of panicking.
- Slot-writer value-slot recording now discards stale top frames before touching payload storage, then routes through the recovery-group path if no valid group frame remains. A corrupt active-group frame cannot turn remember/value-slot access into an active-group unwrap.
- Active-group handle resolution now has fallible production boundaries. Scoped recomposition uses `try_active_group_anchor()`, value-slot recording carries a validated group index into payload storage, recovery value slots use the `GroupStart` anchor they already own, and strict active-group index helpers are test-only.
- Slot scope assignment and lookup now reject duplicate scope owners, stale active-group handles, corrupt active-index entries, and missing group indexes with logged absence instead of unwinding; the existing scope owner remains intact and stale handles cannot alias newly-created or moved groups. Restoring a detached subtree with scope ids that conflict with active groups now clears only the conflicting restored scope ids, preserves the active owner, and lets recomposition attach fresh scopes.
- Slot-writer value slots requested without an active group record into recovery groups at the root cursor and reuse those groups on later passes, so malformed missing-group state is logged and contained inside the slot table instead of aborting.
- Slot active-anchor lookup now validates anchor-registry indexes against the active group table before returning them. Corrupt scope lookups, direct-child lookup under a corrupt parent, stale node owners, stale payload cleanup owners, stale skipped-frame root-node collection, and stale frame skip/end cleanup log absence and no-op rather than indexing outside slot storage. When a reusable active group record is intact but the anchor registry points at the wrong index, the writer repairs the registry from the active group record and reuses the group.
- Ancestor span and node-count propagation stops at corrupt parent anchors through checked active-anchor lookup. The known active group is updated, the broken parent link is logged, and malformed ancestry cannot turn group or node insertion into a panic.
- Ancestor node-count overflow and underflow now repair the affected active group's subtree-node count from physical storage only at the failed delta boundary. Normal node insertion/removal keeps the existing incremental path, while corrupted `subtree_node_count` metadata is reconciled after the physical node mutation without rewriting ancestor counts during active subtree construction.
- Group generation allocation logs and wraps the next counter to `1` after returning `u32::MAX`, so an exhausted generation counter cannot abort group insertion. Active group ids still carry generation plus index; the wrap boundary is explicit and covered by a slot-table regression.
- Group anchor allocation is fallible at the group-insertion boundary. Exhausted dense anchor ids log a checked rejection and return `AnchorId::INVALID` before mutating group storage instead of panicking in `AnchorId::new()`.
- Payload anchor allocation is fallible at value-payload insertion and replacement boundaries. Exhausted dense payload-anchor ids log a checked rejection, return `PayloadAnchor::INVALID` for the injected failure case, and do not mutate group payload storage or advance the writer cursor.
- Group subtree-length lookup now returns logged zero length for missing group indexes instead of indexing group storage directly. Cursor/range callers get a bounded fallback when ownership metadata is already malformed.
- Stale group and payload anchor registry generation updates now log and no-op instead of panicking, while still preserving generation checks so stale handles cannot reactivate or detach reused anchor ids.
- Payload identity replacement now recovers stale payload-anchor records by allocating a fresh active payload anchor and leaving the stale handle inactive, so type replacement cannot abort on corrupted payload-anchor generation state.
- Payload cursor reuse and tail cleanup repair a group's declared payload length against the physical payload segment before indexing or draining, so stale segment metadata cannot turn a composition pass into a payload-range panic.
- Payload range removal validates that the caller-owned group anchor matches the range owner before mutating payload storage. A mismatched owner/range pair logs and no-ops, preserving both sibling payloads instead of aborting on an assertion.
- Payload and node removal validate prebuilt range objects against the current group segment before draining storage. Stale or forged ranges log and no-op, so a detached or reused caller cannot bypass current segment bounds and panic in `Vec::drain`.
- Payload and node segment item insertion repairs the target segment length and rejects missing groups, out-of-range item offsets, overflowing indexes, and indexes past physical storage. Malformed insertion cursors now log and no-op instead of reaching `Vec::insert` or inserting into a neighboring segment.
- Payload and node segment subrange construction now returns a logged empty range for corrupt segment metadata or invalid offsets. Tail cleanup and direct diagnostics no longer reach the old strict segment resolver when a segment start is stale.
- Node cursor reuse and tail cleanup use the same shared segment-length repair path as payloads. Corrupt declared node lengths are reconciled from physical slot storage before node record indexing or tail draining, so node metadata drift is contained at the slot table boundary.
- Detached subtree extraction now repairs removed payload and node segment lengths against the physical boundary before draining storage, so a corrupt child subtree cannot abort during retention, removal, or restore preparation.
- Detached subtree extraction now repairs a corrupt declared group subtree span from active group depth structure before constructing the drain range, so a malformed child cannot abort at range construction or leave descendants orphaned during removal.
- Slot writer group-end and skip cursor advancement now repair the active group's declared subtree span from the retained depth structure before moving parent or child cursors. A corrupt retained span can no longer send writer cursors to a fabricated `u32::MAX` subtree end.
- Skipped-group root-node collection repairs the active subtree span, each group's node segment length, and the root subtree-node count before collecting node records. Malformed retained node metadata can no longer make cleanup iterate a fabricated group range or reserve from stale node-count metadata.
- Detached subtree restore is checked before table mutation. Empty detached subtrees, root-key mismatches, invalid cursor boundaries, attached root parents, bad node lifecycles, active anchors, and root span/count mismatches are logged rejections that return the subtree to the caller. Writer-level rejected restores fall back to normal materialization and carry the rejected subtree to pass finalization for node and payload disposal.
- Detached subtree root-scope lookup is total. Empty malformed detached storage reports no root scope, so retention-mode selection does not reach an infallible root accessor while deciding whether to retain or dispose.
- Composer retention reads detached subtree root keys through checked access. A malformed rootless detached subtree is logged and routed through disposal instead of constructing a retained-key entry from an infallible detached-root accessor.
- Keyed sibling movement validates the destination child cursor, stale root handles, cross-parent roots, and non-earlier insert positions with checked lookups and logged no-ops. A stale root anchor can no longer reach `current_group_index()` through the move path, malformed direct-child move requests leave the active group table unchanged, and the moving root's declared subtree span is repaired from active depth structure before segment rotation.
- Subtree payload/node segment movement repairs affected segment starts and lengths against physical slot storage before rotating item ranges. Corrupt payload or node lengths in a moved keyed sibling can no longer reach slice rotation with an out-of-range item span.
- Keyed sibling search repairs the expected child subtree span before deriving the later-sibling search start. A stale span on the child currently at the cursor can no longer hide the real keyed sibling and force a duplicate insertion.
- Keyed sibling scan and sibling-index construction repair each scanned direct child's subtree span before advancing. A stale span on an intermediate later sibling can no longer skip the real keyed target or build an index from corrupt direct-child boundaries.
- Debug/test-only slot subtree-end helpers are now cfg-gated out of release builds, so Android release compilation stays warning-clean after the structural subtree-span hardening.
- Child-cursor mutation boundaries repair the parent group's declared subtree span from active depth structure before accepting cursor indexes. Group insertion, keyed sibling movement, subtree detachment, and detached subtree restore now reject cursors outside the repaired child range instead of trusting a corrupt parent span until storage insertion or restore mutation.
- Core diagnostic tree dumps report stale applier stable-to-physical mappings as missing physical nodes, so diagnostic output remains available when applier bookkeeping is already suspect.
- Recyclable node emission discards recycle-pool shells with mismatched concrete node type and allocates a fresh id if a recycled stable id is still live, preserving the existing live node. Explicit stable-id insertion also records the requested stable id when reusing a dense physical slot, so compaction preserves the inserted id.
- Node emission no longer aborts on slot-recording postcondition anomalies; it logs the anomaly, queues displaced-node cleanup when available, and continues from the concrete applier node that was emitted or reused. `emit.rs` now has no `panic!` or `expect(` paths.
- Runtime UI continuation dispatch ignores malformed `post_invoke` payload types and keeps the typed continuation registered until the matching payload arrives, so a dispatcher/id mismatch cannot abort the UI thread.
- Runtime UI dispatcher sends roll back their pending-work counter when the receiving runtime channel is already closed, so a dropped runtime cannot leave permanent pending UI work.
- Runtime pending-work guards use a saturating CAS decrement, so a counter already at zero cannot wrap to `usize::MAX` in release builds.
- Runtime task wakers are built from the live runtime inner directly instead of creating a weak pointer and immediately asserting it can upgrade.
- Runtime frame and node-update scheduling helpers ignore and log orphaned requests when no active or retained runtime handle exists on the thread, so callbacks that outlive their runtime cannot panic the caller.
- Snapshot entry and mutable-snapshot event wrappers now restore thread-local runtime flags through drop guards. A panic inside `Snapshot::enter` or `run_in_mutable_snapshot` cannot leak the current snapshot or applied-snapshot marker into later work on the same thread.
- AppShell pointer, key, clipboard, and IME event entry points now use the same guard pattern for the event-handler marker. A panic during input dispatch cannot leave later state writes misclassified as event-handler work, and text-mutating platform events cannot bypass the applied mutable snapshot boundary.
- Focus invalidation processing resets its in-flight marker under unwinding, preserves nodes that were not yet processed, and does not hold the focus-state `RefCell` borrow while invoking processor callbacks. A processor can enqueue follow-up focus invalidations without re-entrant borrow panics, and caught processor panics cannot permanently suppress later focus work.
- Pointer repass processing uses the same short-borrow callback boundary as focus invalidation processing. Pointer processors can enqueue follow-up repasses, and caught processor panics cannot leave pointer repasses permanently stuck in an in-progress state.
- Retention take, insert, and budget eviction use checked detached-subtree validation. Invalid retained node lifecycles reject restore without removing the retained entry; duplicate or malformed inserted retained subtrees are returned to the caller for disposal through the existing evicted-subtree path; malformed evictions are returned instead of panicking.
- MemoryApplier generated high stable ids use the sparse high-id node storage path already used by explicit high ids, so dense physical-slot metadata is not asked to represent ids beyond the dense range.
- Callback holders query the current composer directly before entering a saved callback scope, so forwarder invocation no longer moves the callback through an optional closure slot guarded by a postcondition assertion.
- `ParamSlot::take()` reports absence with `Option<T>` instead of aborting when a generated or manual caller reads before setting the slot.
- Dynamic and static composition-local reads log malformed erased provider entries and return the local default value instead of aborting on type-mismatch postconditions.
- Services composition locals for URI handling, HTTP, and system theme initialize through total default insertion instead of setting an optional slot and asserting the postcondition.
- Native service concurrency reports worker-thread panics as `HttpError::WorkerPanicked`; callers such as the Hacker News demo map batch failures into their existing error flows instead of aborting through a thread-join panic.
- Location-key debug collision tracking records and logs collisions without aborting the process, while keeping the first registered source location as the diagnostic owner for that key.
- Slot writer key/seen tracking promotes inline storage through total `Option::insert` paths instead of setting optional maps and immediately unwrapping the postcondition.
- Subcompose reusable-pool removal now handles stale reusable-count bookkeeping for typed and untyped pools, saturates count correction, removes empty typed pools through checked access, and exits disposal cleanly if active-order bookkeeping is already exhausted.
- Subcompose content-type buckets now remain an index only: typed reusable candidates still pass through `SlotReusePolicy::are_compatible` before the pool removes and returns a node. Same-content-type nodes that a custom policy rejects stay reusable for a later compatible slot.
- Retained-subtree restore removes entries through the same optional map boundary used for lookup, so retention no longer depends on a post-lookup `HashMap::remove(...).expect(...)` invariant.
- Lazy-list measurement telemetry ids are owned by each `LazyListState`; diagnostic measure/pass counters no longer use process-global atomics.
- Text measurement routes through the active `AppContext` via a per-context `TextService`.
- Renderer-provided text services are attached through `Renderer::attach_app_context_services(&AppContext)`; renderers install services into the explicit target context instead of relying on a current-context side effect.
- WGPU and pixels renderers no longer install text measurers as constructor side effects.
- WGPU headless text measurement now returns an explicit `TextMeasurer` for test renderers to attach to their `AppContext`; it no longer mutates outside-context text state as setup.
- Pixels renderer font resources are owned by `PixelsRenderer` and passed explicitly into draw and measurement paths; the pixels renderer no longer keeps a process-global font cache.
- The shared software text backend no longer caches the bundled fallback font in a process-global `OnceLock`; renderers construct and retain their own `SoftwareTextFontSet` / `PixelsTextResources`.
- Public `set_text_measurer` now requires an active `AppContext`, and each new `AppContext` creates its own default `TextService`.
- AppShell tests prove two shells have independent text caches: measuring the same text in one shell neither warms nor invalidates the other shell's cache.
- `TextFieldState::edit()` returns a success flag and rejects nested edits without panicking; text-setter helpers propagate that result.
- The `ios` cargo feature no longer aliases desktop, README/platform docs mark iOS unavailable, demo crates no longer advertise iOS app features, iOS demo build scripts fail clearly, and demo native entry modules no longer expose `ios_main`.
- The WASM scheduler no longer uses an unsafe `Sync` wrapper for frame wakers; `RuntimeScheduler` is native `Send + Sync` and wasm single-threaded, with task wakers routed by runtime id.
- Native `StdScheduler` frame-waker storage recovers poisoned locks and drops replaced wakers outside the lock, so a callback destructor panic cannot permanently break future runtime frame scheduling.
- Android JNI/native-window and WGPU surface unsafe calls are concentrated in `android_jni.rs` and `android_surface.rs`; the general Android runtime and overlay modules call safe wrappers.
- Android WGPU surface creation now returns a typed `AndroidSurfaceError` from the unsafe boundary; surface creation failures are logged by the Android event loop instead of panicking inside FFI glue.
- Android WGPU adapter and device creation failures now also return `AndroidSurfaceError`, so GPU initialization failure is handled through the same runtime error path instead of panicking during surface setup.
- Every discovered workspace crate root now denies unsafe code, including newly added crate roots under `crates`, `apps`, and `xtask`. The Android JNI/surface modules explicitly allow unsafe code as the reviewed platform boundary, and static tests verify the workspace-wide boundary list, crate-root lint coverage, and nearby `SAFETY:` invariants for unsafe blocks.
- `AppContext` routing now uses weak thread-local scope entries; entering a context no longer extends the lifetime of per-window runtime state.
- Dropped `AppContext`s unregister from the thread-local lookup table, so app-context id routing does not retain stale weak entries after shell teardown.
- `AppContext::new()` starts from explicit default density and platform scale enters through `AppShell::set_density()`.
- The desktop-demo web build script now fails on `wasm-pack` errors instead of printing a stale success footer.
- `LayoutRuntimeState` is attached to each `LayoutNode`; child `Measurable` wrappers are reconciled by child id and reused across measure passes, including order changes.
- Retained child measurables clear per-frame builder, applier, error, runtime, and layout-state bindings when node measurement exits, so retaining child identity does not retain the frame arena or applier host past the layout pass.
- Layout modifier coordinator state is retained in an indexed `CoordinatorChain` inside `LayoutRuntimeState`; the hot path no longer allocates boxed coordinator objects for every layout modifier on every measure.
- Retained `ModifierNodeChain` matching includes both element type and node type, and each matched element checks `can_update_node()` before reuse. A retained entry with the wrong concrete node is replaced and detached rather than updated through a downcast-only path.
- Modifier-local reads reconcile erased fallback-cache entries by key type and use the requested key default on provider or ancestor type mismatch, so local propagation cannot abort on a stale cache postcondition.
- Modifier concatenation now uses total single-part extraction after empty short-circuiting, so `Modifier::then()` does not depend on `unreachable!` for enum-state assumptions.
- The stale `MeasurementProxy` layer is removed. Retained coordinators invoke live `LayoutModifierNode` instances directly, so custom layout modifiers keep their node-local state across repeated measurement instead of copying state into detached snapshot objects.
- Lazy-list interval misses produce empty measured items or skipped prefetch work instead of panicking in the layout path.
- Lazy-list bounds adjustment handles empty measured-item slices as a no-op, so the clamp path does not rely on a post-empty-check unwrap.
- Lazy-list key overflow diagnostics no longer use process-global `AtomicBool` suppression state.
- Layout measurement uses a frame-local placement scratch pool, and built-in Box, Row, Column, Spacer/leaf, empty/text, and image measure policies write into caller-owned placement storage.
- Built-in linear layout policies recover missing child placeable slots through an order-preserving child measurement instead of panicking during result assembly.
- `SubcomposeLayout` now retains and recycles placement result storage across measure passes. `SubcomposeMeasureScopeImpl::layout()` writes through retained scratch before returning the public `MeasureResult`.
- LazyColumn/LazyRow placement generation now writes into the subcompose placement scratch with `layout_with_placement_builder()` instead of allocating a fresh placement vector on every lazy-list measure.
- WGPU command encoder creation and command-buffer submission are centralized in `frame_graph.rs` behind `WgpuFrameGraphExecutor`; a source-level test rejects direct encoder creation/submission outside that boundary.
- `WgpuFrameGraph`, command `PassNode`, `PassContext`, `ResourceGraph`, and texture handles now exist as recorded graph data structures, and explicit readback/capture commands route through graph execution.
- Recorded WGPU pass contexts expose the command encoder but not the queue, keeping pass code from performing queue-owned work directly.
- The WASM explicit frame encoder now consumes the command encoder owner on finish and returns transient surfaces through a release-owner drop path. It no longer has a submitted-encoder `Option` state that helper code can trip with a panic.
- Unsupported-effect warning suppression is renderer-owned state, not a process-global WGPU static.
- Pixels renderer warning suppression is scene-owned diagnostic state in `cranpose-render-common`, not process-global atomics.
- Hit dispatch diagnostics are scene-owned; live modifier-slice lookup miss counts travel through retained `RenderDiagnostics` instead of a process-global counter.

## Non-Negotiable Invariants

- One `AppContext` per `AppShell`; density, render invalidation, text cache, node registry, and dirty sets are not process-global.
- Only the WGPU frame graph executor submits command buffers.
- Layout structure is retained; coordinators and child measurables are reconciled by identity and reused.
- Text shaping and measurement are shared explicitly through a per-app text service.
- Platforms are event-driven when idle.
- Unsafe code is quarantined in reviewed platform boundaries, with nearby `SAFETY:` comments documenting ownership and lifetime invariants.
- Platform docs match implementation status.
